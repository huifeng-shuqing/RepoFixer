> 升级前基线：results/real/full（2026-10-23，21/29，72.4%）
> 升级后：results/real_upgraded（2026-10-26，七项升级代码，含任务级容错）
> 口径：deepseek-chat、29 条真实任务、40 步上限、单次运行。

## 一、数据完整性说明（必须先读）

升级后评测当天 DeepSeek API 连接波动严重：29 题中 **4 题两次重试仍失败**（pathspec-c0971a65、pathspec-de045811、pathspec-e51866f2、pathspec-f70a1d2f），被容错机制如实记录为 `llm_error`（0 步、无有效评测）。因此**公平对比样本为 25 题**。此 4 题留待 API 稳定时段补跑（约 ¥1–2）。

## 三、结论（诚实版）

1. **成功率差异（-2 题）在噪声范围内**（n=25 单次运行约 ±8 个百分点），且方向为负——七项升级**未带来可检测的能力提升**。这与三组消融（72.4% ×3）的既有结论一致：本数据集上瓶颈是模型能力，不是 harness 机制。
2. **步数基本持平**（14.2→14.0）。
3. **成本 +20%（+¥0.86/25 题）**是复审调用与每步影子快照的机制开销——这是「可靠性换成本」的真实代价，应如实披露。
4. 七项升级的价值定位：**可靠性、可观测性与工程规范化**（断点续跑、复审、回滚、记忆、MCP、路由），不是峰值能力提升。它们在本数据集上「不帮倒忙、也不加分」。
5. 新加的**任务级容错**在本次网络波动中证明了价值：5 次 API 失败全部被隔离为单任务失败，评测进程零崩溃。

## 四、建议

1. API 稳定时段补跑 4 个 pathspec 任务（约 ¥1–2），补全 29 题全口径数字。
2. 若要进一步提升成功率，**杠杆在模型不在 harness**：用更强模型（deepseek-reasoner / GLM-4.6）跑同 29 题做对照，预期收益远大于继续堆机制。
3. 若重视成本：可配置 `DEEPSEEK_SMALL_MODEL` 启用真正的小模型路由（当前默认回落主模型，路由未生效），把复审/摘要开销降下来。
